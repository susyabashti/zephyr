# Project map

Where every part of Zephyr lives. This file is for **navigation** — read
[features.md](features.md) for user-facing behavior, [plan.md](plan.md) and
[architecture.html](architecture.html) for design, and `spec/` for the byte
contracts. The file index below is **machine-checked**: the `test/structure.py`
gate fails CI if it drifts from `src/`, so it is safe to trust.

## The shape

A local-first, tamper-evident journal CLI whose log is designed to be read by
an AI. The journal is a directory of monthly, hash-chained segment files
(format v1, FROZEN). Derived artifacts (profile, digests, token index, vector
artifact) are pure functions of the verified log. The embedding engine
(pinned llama.cpp + EmbeddingGemma-300M Q8_0) is the only non-std dependency
and is isolated behind a core-side vtable.

## Module graph (mirrors `build.zig`)

```
src/main.zig              thin: dispatch + exit codes
└── src/cli/              one file per command, shared args/errors/journal/output
    ├── zephyr_core       domain logic — no stdout/stderr, no CLI knowledge
    ├── zephyr_mcp        read-only AI server (JSON-RPC over stdio)
    └── zephyr_embed      llama.cpp engine + model fetch (optional: -Dno-embed)
```

Dependencies point one way, always toward `core`. Core defines the embedding
*interface* (`core/embed.zig`); `src/embed/` implements it; tests supply a
deterministic fake.

## Directories

| path | what lives there |
|---|---|
| `src/` | all Zig source: `core/` (domain), `cli/` (commands), `embed/` (engine), `mcp/` (AI server) |

| `zig-out/` | build output (gitignored) |

## The byte contract (how correctness is pinned)

One pattern everywhere: **spec markdown → frozen vectors → two independent
implementations that must agree.** The Python references are deliberate: the
gate is that a second implementation working only from the spec produces
byte-identical output.

| contract | spec | frozen vectors | Zig gate(s) | independent reference |
|---|---|---|---|---|
| record + segment format | `spec/record-format.md` | `spec/vectors/journals.json` | `test/vectors.zig` | `test/reference.py` |
| text rules (frozen NFC subset) | `spec/record-format.md` §4.1 | `spec/data/mark_ranges.txt` | `test/generate_mark_ranges.py` (regenerates the table) | — |
| checkpoint anchors (`.zpa`, Ed25519) | `spec/anchor-format.md` | `spec/vectors/anchors.json` | `test/anchors.zig` | `test/reference.py` + `test/ed25519.py` (RFC 8032 illustration) |
| OTS proofs (`.ots`) | `spec/ots-anchor.md` | `spec/vectors/ots.json` | `test/ots.zig`, `test/phase5b.zig` | `test/otsref.py` |
| derived artifacts (ZDI1 index, digests, profile, ask pack) | `spec/derived.md` §8 | — | `test/phase7.zig` | `test/derivedref.py` |
| semantic layer (ZDE1, fusion, retrieval eval) | `spec/semantic.md` §5–8 | `spec/vectors/embed-labeled.json` | `test/phase8.zig` | `test/semref.py` (`--check` / `--eval`) |
| MCP protocol + tools | `spec/mcp.md` | — | `test/phase6.zig` | `test/mcpref.py` (end-to-end over stdio) |

Behavioral gates that need no reference: `test/phase2.zig` (views, amendments,
tombstones), `test/phase3.zig` (cross-segment round trip + tamper),
`test/phase4.zig` (LLM export refusals), `test/phase5.zig` (redaction +
anchors on a disk journal), `test/roundtrip.zig` (100k round trip; `zig build
roundtrip`, main-only in CI).

## How to find X

| you want to… | go to |
|---|---|
| change the on-disk format | `spec/record-format.md` → `src/core/records.zig` / `segment.zig`; regenerate vectors with `test/reference.py --gen` |
| add a CLI command | copy the shape of `src/cli/commands/search.zig`; register in `src/cli/cli.zig`; add failures to `src/cli/errors.zig` |
| change what a command prints | `src/cli/output.zig` |
| add or change an MCP tool | `spec/mcp.md` → `src/mcp/tools.zig`; gates: `test/phase6.zig` + `test/mcpref.py` |
| change the model pin | `src/embed/model.zig` (the single source) + the CI cache keys in `.github/workflows/ci.yml` carry its sha256 |
| find an environment variable | grep `ZEPHYR_` — `docs/getting-started.md`, `install.sh`, `src/` |
| change build modules, flags, or test wiring | `build.zig` |
| make a release | `docs/releases.md` (tag push does everything) + `.github/workflows/release.yml` |
| read a command's user-facing behavior | `docs/features.md` |
| see the layer diagram | `docs/architecture.html` |
| change agent workflow rules | `AGENTS.md` |

## Structural invariants (enforced by `test/structure.py`)

- `src/core/` imports nothing outside itself and never references
  stdout/stderr — it returns data, it does not print.
- `src/mcp/` and `src/embed/` import only `core` (and their own directory).
- One file per command; a command never imports another command — shared
  helpers live in `src/cli/`.
- The file index above lists every `src/**/*.zig` file exactly; the gate
  fails if a file is added, moved, or renamed without updating this map.
